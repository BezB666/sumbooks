# Глава 16. Data Mesh

- **PDF:** 275–292 (печать 249–266)
- **Якоря:** OLTP, OLAP, data warehouse, data lake, data mesh, fact table, dimension table, CQRS, open-host service

**OLTP** — сущности и транзакции «сейчас». **OLAP** — факты (что произошло) + dimensions, инсайты, ML. **Data warehouse:** ETL из операционки в одну аналитическую БД; часто лезут мимо публичных API в чужие таблицы. **Data lake:** сырой операционный дамп, модели потом; много версий ETL, без схемы легко «болото». Оба ломаются на масштабе и цепляются к implementation model — особенно больно, если операционные модели в DDD часто меняются.

**Data mesh** — DDD для аналитики, четыре принципа: резать данные по доменам (OLAP рядом с BC, та же команда); **data as a product** (порты, схема, SLA, версии, polyglot); платформа для автономии; федеративный governance. Стык с DDD: UL для аналитической модели, аналитика как ещё один published language (**OHS**), **CQRS** для проекций, те же интеграционные паттерны между data products.
