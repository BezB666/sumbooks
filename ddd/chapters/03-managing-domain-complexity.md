# Глава 3. Managing Domain Complexity

- **PDF:** 59–74 (печать 33–48)
- **Якоря:** bounded context, ubiquitous language, subdomain vs bounded context, ownership

Один термин в разных отделах значит разное («lead» в маркетинге — событие интереса, в продажах — весь цикл). Enterprise-wide ERD «для всего» не работает. Решение: разрезать язык на несколько, каждому — явный **bounded context**. UL «ubiquitous» не по всей компании, а внутри своего BC.

**Subdomain** обнаруживают (как устроен бизнес). **Bounded context** проектируют (как режем решение). 1:1 с subdomain бывает, но не обязательно: в одном BC несколько subdomain, у одного subdomain несколько моделей. BC — граница модели, жизненного цикла и ownership: один BC — одна команда (команда может держать несколько BC). Физически BC — отдельный сервис/проект; subdomain внутри — логические модули. Размер: полезность важнее «маленькости»; слишком узко — ад интеграции.
