# Глава 8. Message Transformation (Трансформация сообщений)

- **PDF:** стр. 291–316
- **Роль:** каналы снимают «где живёт получатель». Формат всё ещё связывает. Translator (транслятор) и его варианты.
- **Якоря:** Envelope Wrapper (обёртка-конверт), Content Enricher (обогатитель содержимого), Content Filter (фильтр содержимого), Claim Check (квитанция / багажная бирка), Normalizer (нормализатор), Canonical Data Model (каноническая модель данных), Message Translator (транслятор сообщений)

Интеграция = два параллельных мира: поток сообщений и поток метаданных (схемы). Channel Adapter (адаптер канала) может выгрузить схему в репозиторий, по нему настраивают маппинг на Canonical Data Model.

## Каталог

| Паттерн | Что делает |
|---|---|
| Envelope Wrapper (обёртка-конверт) | тело в конверт, который требует брокер/протокол (SOAP Header, JMS properties, security) |
| Content Enricher (обогатитель) | в целевой системе нужны поля, которых нет у источника — lookup или вычислить |
| Content Filter (фильтр содержимого) | выкинуть лишнее (PII, тяжёлые куски, поля «не для этой системы») |
| Claim Check (квитанция) | вынуть большой/секретный кусок, положить в стор, в сообщении оставить бирку; потом забрать |
| Normalizer (нормализатор) | много входящих форматов → один общий (обычно перед Aggregator/каноникой) |
| Canonical Data Model (каноническая модель) | общий язык шины; каждая система маппит только в канонику и обратно, не N×M |

## Envelope Wrapper (обёртка-конверт)

Несколько конвертов, если сообщение идёт через разные инфраструктуры (как вложенные конверты почты). Снимать в обратном порядке. Родственник: SOAP + WS-Security в гл. 14.

## Enricher vs Filter vs Claim Check (обогатитель vs фильтр vs квитанция)

- Enricher добавляет (кредитный score в гл. 9)
- Filter урезает навсегда
- Claim Check урезает, но данные живы снаружи канала (файл, БД, Message Store / хранилище сообщений). Нужно когда канал не любит мегабайты или посредникам нельзя видеть payload (нагрузку)

## Normalizer vs Canonical Data Model (нормализатор vs каноническая модель)

Normalizer — операционный фильтр «свести вот эти N форматов банков к одному quote». CDM — стратегическое решение всей шины: модель Customer/Order общая. Без CDM каждый новый участник = новые маппинги ко всем. С CDM = два маппинга (in/out).

CDM не бесплатен: кто владеет моделью, версионирование, Format Indicator (индикатор формата).

## Metadata (метаданные)

Картинка главы: App A (имя отдельно, ZIP без штата) ↔ App B (имя одной строкой, штат без ZIP). Трансформация проще, если адаптеры отдали метаданные, а не только примеры сообщений.
