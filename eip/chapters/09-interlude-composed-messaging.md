# Глава 9. Interlude: Composed Messaging (Интерлюдия: составной обмен сообщениями)

- **PDF:** стр. 317–414
- **Это не новые паттерны.** Loan Broker (кредитный брокер): три реализации одного потока. Потом гл. 12 вешает на MSMQ-версию management (управление).
- **Якоря:** Loan Broker (кредитный брокер), Scatter-Gather (разброс-сбор), Content Enricher (обогатитель), Process Manager (менеджер процесса), Recipient List (список получателей), Aggregator (агрегатор)

## Бизнес

Клиент хочет кредит → обычно звонит в несколько банков (SSN, сумма, срок). Банк лезет в бюро кредитов, отвечает ставкой или отказом. Брокер делает это за клиента: один сбор данных, бюро, подходящие банки, лучшая ставка назад.

## Поток паттернами

1. Принять запрос (endpoint / конечная точка — гл. 10, здесь «как-то получили»)
2. Content Enricher (обогатитель) — credit score/history из бюро
3. Ещё enricher / правила — список банков
4. Scatter-Gather (разброс-сбор) — запросы банкам + Aggregator (агрегатор) ответов
5. Message Translator (транслятор) / Normalizer (нормализатор) — у банков разные форматы
6. Лучшая ставка клиенту

Scatter-Gather шлёт через Publish-Subscribe Channel (публикация-подписка) или Recipient List (список получателей).

## Синхронно vs асинхронно

- Sequential (последовательно): спросил банк, ждёт, потом следующий. Проще, медленно, банки простаивают
- Parallel (параллельно): все запросы сразу, ответы в любом порядке. Почти в n раз быстрее, если банки одинаково долгие. Нужны Correlation Identifier (идентификатор корреляции) и агрегатор, который не ждёт порядка

Очередь к бюро: узкое место лечится вторым инстансом бюро — брокер не знает какой инстанс взял сообщение (Competing Consumers / конкурирующие потребители).

## Addressing: distribution vs auction (адресация: распределение vs аукцион)

| Режим | Как | Контроль брокера | Цена |
|---|---|---|---|
| Fixed (фиксированный) | один и тот же список банков | полный | админский ад, банкам сыпятся лишние запросы |
| Distribution (распределение) | Recipient List по критериям (плохой кредит ≠ премиум-банк) | высокий | логика в брокере, канал на каждого банка |
| Auction (аукцион) | pub/sub, банк сам фильтрует (Message Filter / фильтр сообщений / Selective Consumer / избирательный потребитель) | низкий | брокер «без сопровождения», работа на банках; multicast часто не идёт в WAN |

Pub/sub часто эмулируют массивом PTP + Recipient List — семантика та же, каналов больше.

## Ответы: один канал vs канал на банк

Один канал: меньше админки, в ответе должно быть «кто банк», агрегатор не знает N, пока Recipient List не инициализирует его (Initialized Aggregator / инициализированный агрегатор). На аукционе N неизвестно → completeness (полнота) по таймауту / «минимум 3» (хрупко, если банков двое).

## Параллелизм брокера

- Пул инстансов + Message Dispatcher (диспетчер сообщений; предсказуемые ресурсы)
- Один event-driven (событийный) процесс: брокер в основном ждёт ответы, один процесс тянет много inflight, но нужен Process Manager с состоянием на каждый correlation id
