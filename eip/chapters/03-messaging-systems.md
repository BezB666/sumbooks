# Глава 3. Messaging Systems (Системы обмена сообщениями)

- **PDF:** стр. 75–107
- **Роль:** шесть базовых кирпичей. Все остальные паттерны — уточнения этих.
- **Якоря:** Message Channel (канал сообщений), Message (сообщение), Pipes and Filters (трубы и фильтры), Message Router (маршрутизатор сообщений), Message Translator (транслятор сообщений), Message Endpoint (конечная точка)

## Шесть паттернов

| Паттерн | Одна фраза |
|---|---|
| Message Channel (канал сообщений) | договор «куда класть / откуда брать» |
| Message (сообщение) | пакет: header (заголовок) + body (тело) |
| Pipes and Filters (трубы и фильтры) | обработка = цепочка независимых фильтров, каналы = pipes (трубы) |
| Message Router (маршрутизатор) | фильтр, который выбирает исходящий канал, не трогая тело (или почти) |
| Message Translator (транслятор) | фильтр, который меняет формат |
| Message Endpoint (конечная точка) | код приложения, который говорит с брокером |

## Message Channel (канал сообщений)

Приложения не знают друг друга — знают имя канала. Отдельные каналы на типы информации (дальше Datatype Channel / канал типа данных). Кто не умеет в клиент брокера — заходит через Channel Adapter (адаптер канала).

Имена каналов — часть публичного контракта, как URL.

## Message (сообщение)

Единица передачи. Header для брокера (куда, correlation / корреляция, expiration / срок жизни). Body для приложения. Три интента (гл. 5): команда, документ, событие.

## Pipes and Filters (трубы и фильтры)

Каждый шаг — отдельный процесс/компонент. Можно вставлять, убирать, масштабировать шаг, не переписывая соседей. Порядок не обязан совпадать с порядком отправки, если несколько консьюмеров — см. Resequencer (восстановитель порядка). Родня CSP / Unix pipes, но сообщения — структурированные, часто транзакционные.

Связка с Messaging Gateway (шлюз обмена сообщениями): фильтр не обязан светить JMS наружу.

## Message Router (маршрутизатор сообщений)

Канал сам по себе «маршрутизирует» только по подписке. Роутер смотрит свойства сообщения и кладёт в другой канал. Источник не знает конечную точку. Варианты — вся гл. 7. Последовательная обработка 1-в-1, если роутер один и не ветвит.

## Message Translator (транслятор сообщений)

Системы не согласны, что такое Customer. Трансляция на уровнях: транспорт, представление (XML vs запись), данные (поля), семантика. Визуальные мапперы EAI помогают и быстро становятся клеткой. Часто рядом Channel Adapter (адаптер канала).

## Message Endpoint (конечная точка)

Кастомный клей: и приложение, и API брокера (MessageProducer/Consumer, MessageQueue). Дальше вся гл. 10: gateway (шлюз), transactional client (транзакционный клиент), polling vs event-driven (опрос vs по событию).

## Как это складывается

```
App A --Endpoint--> Channel --[Translator|Router|Filter]--> Channel --Endpoint--> App B
```

Шина из каналов + фильтры = интеграционное приложение. Не «вызвал метод на B».
