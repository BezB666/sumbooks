## Четыре вызова любой интеграции

1. Сеть ненадёжна
2. Сеть медленная (на порядки медленнее локального вызова)
3. Любые два приложения разные (язык, ОС, формат)
4. Изменения неизбежны → нужна слабая связанность (loose coupling)

Четыре стиля (разбор в гл. 2): File Transfer (передача файлов), Shared Database (общая БД), Remote Procedure Invocation (удалённый вызов процедуры), Messaging (обмен сообщениями).

## Что такое messaging (обмен сообщениями)

Телефон = синхронно. Автоответчик = очередь сообщений. Messaging: быстрая асинхронная program-to-program (программа-к-программе) связь с надёжной доставкой.

- Канал / очередь — общая коллекция сообщений между машинами
- Sender/producer (отправитель/производитель) пишет, receiver/consumer (получатель/потребитель) читает и удаляет
- Сообщение: header (заголовок; мета для брокера) + body (тело; данные для приложения)
- Body можно читать как данные, команду или событие

## Messaging system (система обмена сообщениями) — пять шагов передачи

1. Create (создать)
2. Send (отправить)
3. Deliver (доставить; брокер)
4. Receive (принять)
5. Process (обработать)

Два свойства: send-and-forget (отправил-и-забыл) у отправителя; store-and-forward (сохранить-и-переслать) у брокера.

## Зачем messaging (выгоды)

- Удалённая связь без RPC-иллюзии
- Платформенная независимость
- Асинхронность: отправитель не ждёт
- Throttling (троттлинг): получатель сам задаёт темп, лишнее копится в канале
- Надёжная доставка
- Disconnected operation (работа в отрыве)
- Медиация: много-ко-многим через каналы

## Чем messaging больно

- Сложнее отладка (нет стека вызовов)
- Нет гарантии *когда* доставят
- Нужно думать асинхронно: Correlation Identifier (идентификатор корреляции), идемпотентность, таймауты
- JMS не стандартизует физический брокер — продукты разные

Синхронный вызов прячет сеть. Асинхронный вызов сеть показывает. Waldo: распределённые объекты — не локальные.

## Distributed apps vs integration (распределённые приложения vs интеграция)

Книга про интеграцию уже существующих приложений, которые часто нельзя менять. Не про написание одной распределённой программы с нуля.
