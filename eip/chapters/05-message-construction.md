# Глава 5. Message Construction (Конструирование сообщений)

- **PDF:** стр. 140–168
- **Роль:** что класть в сообщение, чтобы получатель понял намерение и смог ответить.
- **Якоря:** Command Message (сообщение-команда), Document Message (сообщение-документ), Event Message (сообщение-событие), Request-Reply (запрос-ответ), Return Address (адрес возврата), Correlation Identifier (идентификатор корреляции), Message Sequence (последовательность сообщений), Message Expiration (срок жизни сообщения), Format Indicator (индикатор формата)

## Намерение (три типа тела)

| Паттерн | Смысл | Типичный канал |
|---|---|---|
| Command Message (команда) | «сделай действие» | чаще Point-to-Point (точка-точка) |
| Document Message (документ) | «вот данные, решай сам» | PTP или pub/sub |
| Event Message (событие) | «случилось» | чаще Publish-Subscribe (публикация-подписка) |

Один и тот же байтовый payload (полезная нагрузка) может быть любым из трёх — различает договор и header (заголовок), не XML сам по себе. RPC-обёртка часто = Command. Репликация записи = Document. «цена изменилась» = Event.

## Разговор туда-обратно

**Request-Reply** (запрос-ответ) — пара сообщений, пара каналов (request и reply), не синхронный вызов в одном стеке.

**Return Address** (адрес возврата) — в запросе написано, куда класть ответ. Иначе все отвечают на один фиксированный канал и ответы путаются / нельзя иметь временный reply-queue. Smart Proxy (умный прокси; гл. 11–12) как раз подменяет этот адрес.

**Correlation Identifier** (идентификатор корреляции) — в ответе id запроса. Без него при нескольких inflight (в полёте) не понять, чей reply. Не заменяет Return Address: одно говорит *куда*, другое — *к какому запросу*.

## Большие данные и время жизни

**Message Sequence** (последовательность сообщений) — кусок не влезает / логически список: номер, размер, флаг последнего. Получатель собирает. Не путать с Splitter (разделитель; гл. 7): sequence — про фрагментацию одного логического сообщения.

**Message Expiration** (срок жизни) — TTL. Протухшее не обрабатывать (котировка, устаревший command). Часто уезжает в Dead Letter Channel (канал недоставленных). В гл. 13 expired тики уронили брокер.

**Format Indicator** (индикатор формата) — версия/схема/магическое число в header или в конверте. Чтобы эволюционировать контракт без «все выкатываются в одну секунду».

## Практические связки

- Request-Reply почти всегда: Return Address + Correlation Identifier
- Datatype Channel (канал типа данных): на request-канале один тип запроса
- Invalid Message Channel (канал неверных): пришёл ответ не того типа / без correlation
- Command vs Document: команда подразумевает побочный эффект; документ можно сохранить и обработать позже

## Связанные паттерны

Message Channel (канал сообщений), Point-to-Point Channel (точка-точка), Publish-Subscribe Channel (публикация-подписка), Datatype Channel (канал типа данных), Invalid Message Channel (канал неверных), Dead Letter Channel (канал недоставленных), Smart Proxy (умный прокси), Splitter (разделитель), Message Dispatcher (диспетчер сообщений)
