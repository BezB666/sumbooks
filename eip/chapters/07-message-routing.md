# Глава 7. Message Routing (Маршрутизация сообщений)

- **PDF:** стр. 208–290
- **Роль:** куда сообщение едет. Простые роутеры, составные, архитектурные.
- **Якоря:** Content-Based Router (маршрутизатор по содержимому), Message Filter (фильтр сообщений), Dynamic Router (динамический маршрутизатор), Recipient List (список получателей), Splitter (разделитель), Aggregator (агрегатор), Resequencer (восстановитель порядка), Scatter-Gather (разброс-сбор), Routing Slip (маршрутный лист), Process Manager (менеджер процесса), Message Broker (брокер сообщений)

Три группы: simple routers (простые маршрутизаторы), composed routers (составные), architecture (архитектура: Process Manager, Message Broker).

## Simple routers (простые маршрутизаторы)

| Паттерн | In → Out | Stateful? | Суть |
|---|---|---|---|
| Content-Based Router (по содержимому) | 1 → 1 канал | нет | смотрит тело/поля, кладёт в один исходящий |
| Message Filter (фильтр) | 1 → 1 или 0 | нет | пропускает или выкидывает |
| Dynamic Router (динамический) | 1 → 1 | да (правила) | правила приходят на control-порт (порт управления) |
| Recipient List (список получателей) | 1 → N каналов | нет | явный список получателей, контроль кто получит |
| Splitter (разделитель) | 1 → N сообщений | нет | список в теле → по сообщению на элемент |
| Aggregator (агрегатор) | N → 1 | да | родственные сообщения в одно |
| Resequencer (восстановитель порядка) | N → N | да | восстановить порядок; публикует столько же, сколько съел |

CBR vs массив фильтров на pub/sub: CBR предсказывает один канал и знает все назначения (контроль, связанность). Фильтры реагируют локально, никто не знает полный список (гибкость, сложнее гарантия «ровно один»).

Message Filter vs Selective Consumer (избирательный потребитель): фильтр — часть messaging-потока, пишет в другой канал. Selective Consumer — в endpoint (конечной точке), сообщение даже не выходит «наружу» другому компоненту.

Recipient List vs pub/sub: список — когда брокер/отправитель решает кто; pub/sub — когда получатели сами подписываются.

Aggregator: completion condition (условие завершения: все части / таймаут / первое хорошее / N из M). Без условия — вечная память.

Resequencer: буфер, дырки в номерах, риск unbounded buffer (неограниченного буфера) если потерян кусок — нужен TTL/DLQ.

## Composed routers (составные маршрутизаторы)

| Паттерн | Склейка | Зачем |
|---|---|---|
| Composed Message Processor (составной обработчик) | Splitter → обработка по штуке → Aggregator | заказ из строк, строки разными системами, потом снова заказ |
| Scatter-Gather (разброс-сбор) | разослать (pub/sub или Recipient List) + Aggregator ответов | лучшая цена / все статусы |
| Routing Slip (маршрутный лист) | в сообщении список шагов | маршрут известен заранее, хопы независимы |
| Process Manager (менеджер процесса) | внешнее состояние процесса, сообщение = событие | маршрут зависит от ответов, ветвления, долгие ждуны |

Routing Slip vs Process Manager: slip легче и без центра, но плохо меняет путь на лету. Process Manager тяжелее, держит состояние (Loan Broker в гл. 9).

Scatter-Gather: см. гл. 9 — distribution (распределение; Recipient List) vs auction (аукцион; pub/sub).

## Архитектура

**Message Broker** (брокер сообщений) — центральный хаб маршрутизации (часто EAI-продукт). Плюс: одна точка правил. Минус: хаб = точка отказа и связанности со всеми форматами, если нет каноники.

Не путать с Loan Broker (бизнес-посредник) и Message Bus (шина сообщений; гл. 4 — инфраструктурный стиль). Broker — про маршруты; Bus — про общую шину и подключение.
