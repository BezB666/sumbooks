# Глава 11. Object-Relational Behavioral Patterns

- **PDF:** 208–239 (печать 183–214)
- **Якоря:** Unit of Work, Identity Map, Lazy Load

Не «как колонка ↔ поле», а когда читать/писать и как не разъехаться.

| Паттерн | Когда |
|---|---|
| Unit of Work | надо знать, что трогали, и синхронизировать память с БД одним commit (порядок, целостность, пакет SQL). Особенно Domain Model и бизнес-транзакции через несколько системных. Альтернативы (save сразу / dirty flags) быстро ломаются на графе объектов |
| Identity Map | объект из БД, который можно менять: две копии одной строки в памяти = порча. Побочно — кэш чтений. Не обязателен для иммутабельных Value Object и Dependent Mapping |
| Lazy Load | не тащить весь граф одним чтением; поле в той же строке ленивить почти бессмысленно. Осторожно с коллекциями: поштучная лень → ripple loading. Разные use case хотят разную лень |
