# Глава 2. Organizing Domain Logic

- **PDF:** 50–57 (печать 25–32)
- **Якоря:** Transaction Script, Domain Model, Table Module, Service Layer, Record Set, use-case controller

**Transaction Script** — процедура на действие пользователя: просто, стыкуется с Gateway, границы транзакции очевидны; при росте логики — дубли. **Domain Model** — классы вокруг существительных домена; сложные правила держит (стратегии вместо `if`), цена — привыкание и почти всегда Data Mapper. **Table Module** — один экземпляр на таблицу, работает над Record Set; структурированнее скриптов, без полиморфизма модели. Силён, где GUI уже на Record Set (.NET); без такого тулинга Fowler его не берёт.

Выбор по сложности домена (измерить нельзя). Команда, умеющая в объекты, сдвигает порог к модели. Из скриптов в модель рефакторить стоит; обратно — редко. Паттерны можно мешать.

**Service Layer** поверх модели или Table Module: API, транзакции, security. Минимум — фасад; максимум — скрипты в сервисе и тонкие объекты (Active Record). Середина controller-entity Fowler не любит (дубли). Предпочитает самый тонкий слой, часто без него; Stafford — богатый Service Layer.
