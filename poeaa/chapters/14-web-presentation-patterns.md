# Глава 14. Web Presentation Patterns

- **PDF:** 354–411 (печать 329–386)
- **Якоря:** MVC, Page Controller, Front Controller, Template View, Transform View, Two Step View, Application Controller

Разбор ролей из гл. 4. MVC: отделять модель от UI почти всегда, как только есть невизуальная логика; view vs input controller на вебе полезно, на rich client — редко.

| Паттерн | Когда |
|---|---|
| Model View Controller | модель с поведением; смена/тест UI без домена. Не стоит только в совсем тупых экранах без логики |
| Page Controller | привычная навигация «действие ≈ страница/скрипт»; сайт скорее документный, контроллер прост. Сложная навигация — смотреть Front Controller |
| Front Controller | один вход в веб-сервер, дальше команды; меньше конфигов сервера, динамические команды. Дороже Page Controller — окупается на сложном потоке экранов |
| Template View | страница как макет (часто server page) + маркеры; есть HTML-редакторы. Логику не в scriptlet — в helper. Иначе JSP/ASP быстро становятся худшим кодом |
| Transform View | команда мыслит трансформами (XSLT/XML); легче тестировать без веб-сервера; один stylesheet на J2EE и .NET. Минус — XSLT и слабый тулинг (срез книги) |
| Two Step View | один второй этап на всё приложение: общий look, мультибренд (авиасайты с разной обёрткой), разный device при общем logical screen. Сильно дизайнерские уникальные экраны — не сядет |
| Application Controller | машина решает порядок экранов и вид от состояния объектов. Если любой экран в любом порядке — не нужен |
