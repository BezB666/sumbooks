# Глава 12. Resiliency

- **PDF:** 413–444 (печать 387–418)
- **Якоря:** timeout, retry, bulkhead, circuit breaker, isolation, redundancy, idempotency, HTTP GET, HTTP PUT, CAP, chaos engineering

Паттерны устойчивости: timeout, retry, bulkhead, breaker, изоляция, избыточность, middleware. **Идемпотентность** (печать 406, PDF 432–433): исход бизнес-операции не меняется после первого применения; retry и replay сообщений безопасны. Пример: кредит баллов без ключа заказа — не идемпотентен; с `forPurchase` — да. Логи и метрики при повторе писать можно. GET/PUT в HTTP-спеке идемпотентны **только если сервис так обрабатывает**; протокол сам по себе бесплатно не даёт. Таймаут (гл. 4) закрывается отсюда. CAP и chaos — дальше по главе.
