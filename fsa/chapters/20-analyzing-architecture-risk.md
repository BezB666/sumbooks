# Глава 20. Analyzing Architecture Risk (Анализ архитектурных рисков)

- **PDF:** 387–410 (печать 375–398)
- **Якоря:** risk matrix (матрица рисков), risk assessment (оценка рисков), risk storming (штурм рисков)

**Risk matrix** (матрица рисков): impact (влияние) × likelihood (вероятность), каждое 1/2/3. 1–2 green (зелёное), 3–4 yellow (жёлтое), 6–9 red (красное). Пример: падение БД = высокий impact, низкая вероятность → 3, не 9. Assessment-таблица (таблица оценки) по кускам системы; фильтр «только красное»; стрелка тренда (fitness functions / фитнес-функции показывают направление).

**Risk storming** (штурм рисков) — совместная сессия: один архитектор не видит всё. Измерения: unproven tech (непроверенная технология), performance (производительность), scalability (масштабируемость), availability (доступность), data loss (потеря данных), SPOF (единая точка отказа), security (безопасность). Сначала индивидуально на диаграмме, потом сведение расхождений. Можно накладывать на Agile-стори.
