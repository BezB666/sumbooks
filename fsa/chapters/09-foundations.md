# Глава 9. Foundations (Основы)

- **PDF:** 168–185 (печать 156–173)
- **Якоря:** architecture style (стиль архитектуры), architecture pattern (архитектурный паттерн), Big Ball of Mud (большой ком грязи), unitary (унитарный), monolithic (монолитный), distributed (распределённый), fallacies of distributed computing (заблуждения распределённых вычислений)

**Style** (стиль) — как устроены UI, бэкенд и datastore (хранилище данных; слои монолита vs отдельно деплоемые сервисы). **Pattern** (паттерн) — более низкий приём внутри стиля (как добиться scale/perf / масштаба/производительности). Стили несут известный набор trade-offs (компромиссов).

База: **Big Ball of Mud** (большой ком грязи), **unitary** (унитарный; всё в одном процессе). Классификация: **monolithic** (монолитный; один деплой) vs **distributed** (распределённый; несколько юнитов по сети). У distributed общие боли: 8 fallacies (заблуждений; сеть надёжна / latency = 0 / bandwidth бесконечен / сеть безопасна / топология не меняется / один админ / транспорт бесплатен / сеть однородна) плюс согласованность данных.
