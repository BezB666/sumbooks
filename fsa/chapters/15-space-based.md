# Глава 15. Space-Based Architecture Style (Пространственный стиль архитектуры)

- **PDF:** 279–311 (печать 267–299)
- **Якоря:** Space-Based (пространственный), processing unit (единица обработки), data grid (сетка данных), data pump (насос данных), replicated cache (реплицированный кеш), distributed cache (распределённый кеш)

Классический треугольник web → app → DB: bottleneck (узкое место) всегда уезжает вниз к БД. Space-Based убирает БД из hot path (горячего пути): **processing units** (единицы обработки) с in-memory grid (сеткой в памяти), **virtualized middleware** (виртуализированное промежуточное ПО), **data pumps / writers / readers** (насосы / писатели / читатели данных) догоняют систему записи. Реплицированный кеш быстрый, но бьётся о большие объёмы и частые апдейты; distributed (распределённый) — наоборот. Примеры: тикеты на концерт, аукцион.

**5★** elasticity (эластичность), scalability (масштабируемость), performance (производительность). **Testability** (тестируемость) 1 (пиковую нагрузку почти не смоделировать). **Simplicity** (простота) низкая (eventual consistency / eventual-согласованность, потеря данных). Дорого (лицензии кеша, ресурсы). Партиционирование смешанное: processing unit как доменный сервис + технический конвейер кеш → pump → DB.
