# Глава 1. Introduction (Введение)

- **PDF:** 13–39 (печать 1–27)
- **Якоря:** software architecture (программная архитектура), architecture characteristics (характеристики архитектуры), architecture decisions (архитектурные решения), design principles (принципы проектирования), First Law (первый закон), Second Law (второй закон), intersection (пересечение)

Архитектура ≠ «это microservices (микросервисы)». Определение книги: **structure** (структура, стиль) + **architecture characteristics** (характеристики архитектуры; жаргон: ilities / на «-ость»; критерии успеха, ортогональные функциональности) + **architecture decisions** (архитектурные решения) + **design principles** (принципы проектирования). Johnson/Fowler: important stuff, whatever that is (важное — что бы это ни было).

Ожидания от архитектора (не должность): решения, непрерывный анализ, тренды, compliance (соответствие требованиям), широта опыта, знание домена, soft skills (мягкие навыки), политика. Пересечения: engineering practices (инженерные практики; iterative / итеративные из-за unknown unknowns / неизвестных неизвестных; «all architectures become iterative» — «все архитектуры становятся итеративными»), **process** (процесс; Waterfall / водопад плохо стыкуется с современными стилями), **ops/DevOps** (эксплуатация/DevOps; эластичность раньше вшивали в архитектуру, МС отдают эксплуатации).

**First Law** (первый закон): everything is a trade-off (всё — компромисс; corollary / следствие: если trade-off / компромисс не виден — ещё не нашли). **Second Law** (второй закон): why (почему) важнее how (как).
