# Глава 2. Discerning Coupling in Software Architecture (Различение сцепления в архитектуре)

- **PDF:** 46–75 (печать 34–63)
- **Якоря:** architecture quantum (квант архитектуры), static coupling (статическое сцепление), dynamic coupling (динамическое сцепление), communication (коммуникация), consistency (согласованность), coordination (координация)

Часть I — Pulling Things Apart (разбираем по частям): как в детстве понять механизм — сначала разобрать. Page-Jones: coupling (сцепление) бывает **static** (статическое — как сварено: зависимости, точки соединения, видно на compile-time) и **dynamic** (динамическое — как зовут в рантайме: протокол, что передают, жёсткость контракта). Trade-off analysis (анализ компромиссов) буксует, пока силы спутаны, как коса: не видно отдельных прядей. Метод книги: 1) найти запутанные измерения, 2) понять, как они сцеплены, 3) оценить цену изменения.

**Architecture quantum** (квант архитектуры) — независимо деплоимый артефакт с высокой функциональной связностью, высоким static coupling внутри и синхронным dynamic coupling снаружи. Практический тест: что нужно поднять с нуля, чтобы этот кусок *работал*? Сюда входит не только код, но и БД, брокер, если без них сервис не стартует. Монолит + одна БД = один quantum. Shared DB (общая БД) между «сервисами» схлопывает их в один квант, даже если процессы разные. Жёстко пришитый UI, общий оркестратор — тоже coupling points (точки сцепления). В микросервисах без общих точек — квант на сервис; micro-frontend (микрофронтенд) может снова склеить сервис и UI в один квант.

Static coupling отвечает на вопрос «что уедет вместе при изменении». Dynamic — «как кванты общаются в workflow (потоке работ)». Три оси dynamic coupling, которые дальше дают матрицу восьми саг (гл. 12):

- **communication** (коммуникация): sync (синхронно, жду ответ) vs async (асинхронно, отправил и живу дальше);
- **consistency** (согласованность): atomic (всё или ничего) vs eventual (потом догонит);
- **coordination** (координация): orchestration (оркестрация, есть дирижёр) vs choreography (хореография, сервисы сами реагируют на события).

Sync-вызов связывает operational characteristics (операционные характеристики) вызывающего и вызываемого: если Assignment синхронно зовёт Ticketing, эластичность Assignment ограничена Ticketing. Присутствие брокера в деплое — static; вызов через брокер в рантайме — dynamic.
